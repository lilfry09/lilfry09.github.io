# 读《Reasoning with Sampling》：RL 没让模型变聪明，它只是在重分配推理能力


这篇论文最有意思的地方，不是它提出了一个新采样器，而是它在追问一个更危险的问题：

**我们今天看到的 reasoning 提升，到底来自模型学会了新能力，还是只是把原本分散在多次采样里的能力，重新压缩到单次回答里？**

这个问题一旦问出来，整篇论文的味道就变了。

它不再只是“再来一个 decoding trick”，而是在重新审视 `RL for reasoning` 这条路线的解释权。

## 1. 问题定义 (Task)

先把表象拨开。

这篇论文真正要解决的，不是“怎么训练一个更强的模型”，而是：

**给定一个已经训练好的 base model `p(x)`，在不改权重的前提下，能不能通过额外的推理计算，把更高质量的完整推理轨迹更稳定地采出来？**

如果形式化一点，它要做的是从一个新的目标分布里采样：

`q_alpha(x) = p(x)^alpha / Z_alpha`

其中 `alpha > 1`，表示我们希望把原始分布里那些本来就更高概率的序列进一步放大。

这意味着什么？

意味着问题的本质，不再是“学习一个新函数”，而是“重新设计一个采样分布”。

所以它更像一个带计算预算约束的推理优化问题：

- 已知：base model `p(x)` 已经固定
- 目标：提高 single-shot 的成功率
- 手段：用更多 inference-time compute 逼近更理想的采样分布
- 约束：尽量不靠 RL 那样改权重、改行为分布

从这个角度看，这篇论文的核心战场其实不是训练，而是**分布操控**。

## 2. 破局点 (Challenge)

在这篇论文之前，主流路线大概有两类。

第一类是最直接的：`RL post-training`。

直觉上它很顺：

- 模型单次回答不够强
- 那就给奖励，往“更像正确答案”的方向调权重
- 这样 single-shot 就会变强

但从第一性原理看，这条路有一个不够优雅的地方：

**它把“答得更稳”和“真的学会新能力”默认成了同一件事。**

而论文想指出，未必如此。

如果一个 base model 在 `pass@k` 里本来就已经能靠多次尝试找到正确解，那说明这些正确路径本来就已经存在于分布里。  
RL 做的，也许只是把这部分概率质量往 one-shot 上集中，而不是凭空创造了新路径。

第二类是更朴素的推理策略，比如低温采样。

这条路的问题也很明显：

- 它确实会让输出更稳
- 但它是逐 token 地局部变贪心
- 它优化的是局部 next-token 分布，不是完整推理轨迹

所以它看起来像在变强，实际上更像是在做局部锐化，而不是全局重排。

最后还有一个工程层面的难点：

即便你知道理想分布是 `p(x)^alpha`，你也不能简单粗暴地对整条序列做 MCMC。  
因为序列空间太高维，整句级别的采样会遇到非常糟糕的 mixing 问题。[ar5iv HTML](https://ar5iv.org/html/2510.14901v1)

所以主流方法各有问题：

- RL 太重，而且解释未必干净
- 低温太局部，不是真正的全局分布修正
- 直接 MCMC 又太难算

这才是这篇论文真正接住的缝隙。

## 3. 灵感与火花 (Insight & Novelty)

### 灵感来源 (Inspiration)

这篇论文最核心的灵感，其实很像统计物理和能量模型里的常识：

**如果你想让系统更偏向低能量、高质量状态，一个自然做法不是重写系统本身，而是改变采样分布。**

把 `p(x)` 提到 `alpha` 次方，本质上就是在做分布锐化。  
它不是发明新的解，而是让原本就更优的解更容易被抽到。

### 本质洞察 (Insight)

论文最重要的洞察，我觉得可以压成一句话：

> RL 的很多收益，可能不是“增长了能力”，而是“重分配了能力”。

这个洞察一下子修正了一个常见偏见：

过去我们容易把 `single-shot` 看成模型真实能力，把 `pass@k` 看成额外采样收益；  
但这篇论文反过来说，也许 `pass@k` 才更接近模型内部真实的能力储备，而 `single-shot` 只是这个储备被取出来的效率。

如果真是这样，那问题就从“如何继续训练”转成了：

**如何在不破坏多样性的前提下，更高效地把已有能力采出来？**

### 创新表达 (Novelty)

【痛点】：RL 提升了单次表现，但可能伴随分布塌缩和多样性损失  
【启发】：真正值得关注的，也许是能力在 `pass@k` 和 `single-shot` 之间如何重分配  
【设计】：把目标从“学新参数”改成“采新分布”，直接考虑 `p(x)^alpha`

【痛点】：低温采样只是在局部 token 分布上变贪心，不能代表完整轨迹质量  
【启发】：推理质量属于整条路径，而不是每一步的局部最优  
【设计】：对整条序列的联合概率做幂次锐化，而不是只改 next-token temperature

【痛点】：目标分布 `p(x)^alpha` 很难直接采样  
【启发】：MCMC 天生就是为“只能算相对概率、不能直接归一化采样”的目标分布准备的  
【设计】：用 `Metropolis-Hastings` 近似从 power distribution 中采样

【痛点】：整条序列上的 MCMC 在高维空间 mixing 太慢  
【启发】：LLM 本身是自回归的，前缀扩展天然提供了一条从低维到高维的桥  
【设计】：构造 blockwise 的中间分布，先采短前缀，再逐步扩成长前缀，用 warm start 避免整句采样爆炸

## 4. 假如是你，会怎么想？ (Motivation)

如果按第一性原理去想，我觉得这条思路其实非常顺。

既然很多 base model 在 `pass@k` 下本来就能做对不少题，那是不是说明“正确解”其实早就在模型分布里了？

如果这些解本来就在，那 RL 提升的到底是什么？  
是模型突然变聪明了，还是它只是更容易在第一次就走到那条本来就存在的正确路径？

如果是后者，那我们为什么非要改权重？  
既然问题出在“抽得不准”，那为什么不直接改采样？

可改采样又该怎么改？  
如果我们只是把 temperature 调低，那本质上是在每一步都更贪心。但推理真的等于每一步局部更贪心吗？显然不等于。

那真正想要的是什么？  
不是某一个 token 更大概率，而是**整条完成后的推理轨迹**更大概率。

既然如此，为什么不直接定义一个更偏向高质量完整轨迹的新分布，比如 `p(x)^alpha`？

可新的问题又来了：这个分布没法直接 sample，怎么办？  
那不就是 MCMC 的典型场景吗？

可整句 MCMC 又为什么不现实？  
因为序列太长、空间太大，直接在整条句子上游走几乎必然混得很慢。

那 LLM 有没有给我们现成的结构可用？  
有，自回归。

既然是自回归，为什么不先在短前缀上找到一个靠谱状态，再逐步往后长？  
如果每一步都只扩一个 block，并且以前一步结果做 warm start，那整件事是不是就从“在超高维空间里瞎走”，变成了“沿着生成过程逐级修正”？

顺着这串问句走下去，`Reasoning with Sampling` 基本就不是拍脑袋，而是一个相当自然的答案。

## 5. 鸡蛋里挑骨头 (Potential Flaw)

### 局限性

这篇论文最漂亮的地方，在于它把问题重新定义成“采样”；但它的边界也恰恰在这里。

因为它默认了一个很强的前提：

**高质量答案在 base model 概率分布里本来就已经占据相对高的位置。**

如果这个前提成立，power sampling 会很有力；  
如果这个前提不成立，事情就麻烦了。

比如在一些需要外部验证、世界知识更新、或者长程事实约束的任务里，base model 可能会对“看起来很顺的错误答案”也给出很高概率。  
这时 `p(x)^alpha` 只是把自信的错答案变得更自信。

### 潜在困难

如果数据分布很“不怀好意”，比如：

- 正确答案在语言上并不流畅，反而需要跳出常见模式
- 模型对幻觉式解释天然更高置信
- 任务质量不能由 likelihood 很好代理
- 真正的关键决策只发生在少数几个 pivot token 上

那这种方法会有一种很典型的挫败感：

**它会在错误的山峰上爬得越来越认真。**

这不是采样器不努力，而是目标分布本身就没有把“真正确”表达干净。

再加上它的计算成本也不低。论文里给出的 token 成本量级大致是 `O(T^2)`，这说明它更像一种 test-time scaling 方法，而不是一个几乎免费的推理增强。[ar5iv HTML](https://ar5iv.org/html/2510.14901v1)

### 挖坑（未来方向）

我觉得最值得继续挖的一条线是：

**把 power sampling 和外部 verifier、过程奖励、或者 learned proposal 结合起来。**

更具体地说，有三个很有价值的问题：

- 能不能只在真正关键的局部位置上做重采样，而不是整段后缀都反复生成？
- 能不能用 verifier 去修正“高 likelihood 不等于高正确率”这个根本缺口？
- 能不能学出一个更好的 `proposal model`，让 MCMC mixing 更快、更省？

这条线之所以有顶会味道，是因为它开始真正触碰“sampling 与 reasoning objective 不一致”这个核心问题。

## 6. 总结与启发 (Reflections)

如果把这篇文章的方法论抽象出来，它其实能迁移到很多别的领域：

- 能量模型里的 test-time refinement
- 规划问题里的轨迹采样
- 程序搜索里的候选重排
- 蛋白质、分子、代码生成这类“整条序列质量比局部 token 更重要”的任务

它带来的最大启示，我觉得不是某个具体算法，而是一种认知翻转：

> 有时候问题不在于模型没有能力，而在于我们不会从它已有的能力里取样。

这个启示非常大。

因为它提醒我们，`learning` 和 `extraction` 是两回事：

- 有的提升来自学习新能力
- 有的提升来自更好地抽取旧能力

而 `Reasoning with Sampling` 最有价值的地方，就是把这两者分开了。
