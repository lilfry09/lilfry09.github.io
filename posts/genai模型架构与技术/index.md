## CLIP
CLIP 模型（Contrastive Language–Image Pre-training，对比语言-图像预训练）的基本结构相对简洁且高度模块化。它主要由**两个独立的编码器**和一个**对比学习目标函数**构成，这两个编码器将图像和文本映射到同一个**联合嵌入空间**中。

CLIP 模型的基本结构如下：
### 1. 图像编码器（Image Encoder）

*   **功能：** 接收原始图像作为输入，并将其转换为一个固定长度的**图像嵌入向量**（Image Embedding）。
*   **常用架构：**
    *   最初的 CLIP 论文采用了两种主要的视觉 Transformer 变体：
        *   **ResNet-50 的改进版本：** 结合了 Attention 机制和一些性能改进。
        *   **Vision Transformer (ViT)：** 图像被分割成一系列的 patch，然后输入到标准的 Transformer 编码器中进行处理。
*   **输出：** 一个代表图像语义内容的 $N$ 维向量。

### 2. 文本编码器（Text Encoder）

*   **功能：** 接收描述图像的文本（即 Caption 或 Prompt）作为输入，并将其转换为一个固定长度的**文本嵌入向量**（Text Embedding）。
*   **常用架构：**
    *   一个**因果自注意力 Transformer** 的变体（如 GPT-2 或类似 Transformer 解码器的结构），用于处理文本序列。
*   **输出：** 一个与图像嵌入向量**维度相同**的 $N$ 维向量。

### 3. 联合嵌入空间（Joint Embedding Space）

*   这是 CLIP 的核心所在。图像编码器和文本编码器的目标是将各自的输入映射到一个**共享的、多模态的向量空间**中。
*   **特性：** 在这个空间中，**相互匹配**的图像和文本（即描述同一事物的图文对）它们的嵌入向量会彼此**靠近**，而**不匹配**的图文对的嵌入向量则会彼此**远离**。

### 4. 训练目标：对比学习（Contrastive Learning）

CLIP 的训练不是传统的分类或回归任务，而是一个**对比学习**任务：

*   **输入：** 在一个训练批次中，包含 $N$ 个（图像，文本）对。
    *   这会产生 $N$ 个图像嵌入 ($I_1, I_2, ..., I_N$) 和 $N$ 个文本嵌入 ($T_1, T_2, ..., T_N$)。
*   **相似度矩阵：** 模型会计算所有 $N \times N$ 种可能的图像和文本组合之间的**相似度得分**（通常使用**余弦相似度**）。
*   **目标：**
    *   **最大化**对角线元素（即**正确的图文对**：$(I_i, T_i)$）的相似度得分。
    *   **最小化**非对角线元素（即**错误的图文对**：$(I_i, T_j)$，其中 $i \neq j$）的相似度得分。

通过这种方式，CLIP 学习了**文本和图像之间的关联性**，从而使其具备了强大的**零样本迁移**和**跨模态检索**能力。

---
*在 HunyuanImage 3.0 中，虽然没有直接使用 CLIP 架构，但其 **Vision Encoder** 的设计目的（提取语义特征并对齐到 LLM 空间）与 CLIP 的图像编码器在功能上是一脉相承的。*



## Gemini&Nano-banana：原生多模态架构
1. **单一模型统一处理所有模态：**
    
    - **不同于“拼接”**：早期的系统通常是分别训练一个文本 LLM、一个视觉模型（如 CLIP），然后用一个小的连接器（如 Projection Layer）将它们拼在一起。
        
    - **Gemini 的原生统一**：Gemini 2.5 Pro 从头开始训练，它将**文本、图像、音频甚至视频帧**等所有模态的数据，都转换成了**统一的 token** 或嵌入格式。
        
    - **单个 Transformer 骨干网络：** 所有这些统一的 token 流入**同一个巨大的 Transformer 骨干网络**中进行处理。这个网络可以同时理解和推理不同模态之间的复杂关系。

#### 原生MLLM的挑战

现有的多模态大模型（MLLM）通常采用视觉编码器-对齐模块-语言模型的结构，将视觉编码和语言解码分别进行处理，通常通过将预训练的视觉编码器（例如CLIP）与大语言模型（LLM）结合来实现，即**模块化**MLLM。最近新兴的[Chameleon](https://zhida.zhihu.com/search?content_id=249835414&content_type=Article&match_order=1&q=Chameleon&zhida_source=entity)、[EVE](https://zhida.zhihu.com/search?content_id=249835414&content_type=Article&match_order=1&q=EVE&zhida_source=entity)等**原生**MLLM将视觉感知和多模态理解直接集成到一个LLM中，可以更方便地通过现有工具进行部署、具备更高的推理效率。然而，由于**灾难性遗忘**问题，现有原生MLLM的性能仍显著低于模块化MLLM。



## 混元3d：
#### 1. 基础架构和高效能设计

- **MoE（专家混合）LLM 基座：** HunyuanImage 3.0 基于内部预训练的 **Hunyuan-A13B** 模型，这是一个**解码器-only** 的 **MoE 大语言模型 (LLM)**。
    
    - **规模与效率：** 总参数超过 **800 亿**，但在推理时每 token 仅激活 **130 亿**参数，使其成为迄今为止**最大、最强大的开源图像生成 MoE 模型**。这种设计平衡了高模型容量和计算效率。
        
- **原生多模态统一框架：** 模型在一个**混合离散-连续**建模策略中统一了文本和图像。
    
    - **单序列统一：** 采用了**双编码器策略**，将 **VAE** 提取的潜特征与**视觉编码器**提取的特征连接起来，实现了在**单个序列**内同时支持图像生成和图像理解的统一多模态表示。
    - **混合离散-连续建模策略: 
    - **离散（Discrete）：** **文本（Text）** 模态被视为离散的 token，模型通过标准的 **自回归（Autoregressive）** 方式进行下一个 token 的预测（next-token prediction），这是 LLM 的传统工作方式。
	- **连续（Continuous）：** **图像（Image）** 模态被视为连续的潜特征（latent features），模型通过 **扩散（Diffusion）** 机制进行预测。
    
	HunyuanImage 3.0 的核心在于，它将一个 **解码器-only 的 MoE LLM**（Hunyuan-A13B）作为骨干网络，并将其扩展为能够同时处理这两种性质信息的统一序列模型。
#### 双编码器策略与特征连接
为了让骨干网络同时具备“理解”和“生成”图像的能力，模型引入了**双编码器（Dual-Encoder）** 策略：

|                                      |                                                                                             |            |
| ------------------------------------ | ------------------------------------------------------------------------------------------- | ---------- |
| 编码器                                  | 角色与功能                                                                                       | 目标任务       |
| **内部 VAE (Variational Autoencoder)** | **生成（Generation）**：将原始像素值投影到 32 维的潜在空间，降采样因子为 16。它提供**高保真度**、**结构化**的图像潜特征，是扩散模型生成高质量图像的基础。 | 图像生成 (T2I) |
| **预训练视觉编码器 (Vision Encoder)**        | **理解（Understanding）**：从图像中提取高级的**语义特征**。它捕获了图像的内容、概念和上下文，以便模型能够进行多模态理解任务（如图像问答、图像编辑等）。      | 图像理解 (MMU) |

**特征连接（Concatenation）：**

- 这两个编码器提取的特征（VAE 潜特征和 Vision Encoder 特征）都通过各自的 **投影层（Projector）** 转换。
    
- 这些投影层将原始特征映射到 **与 LLM 词嵌入（Word Embeddings）兼容的联合嵌入空间（Joint Embedding Space）** 中。
    
- 最终，**这些特征被连接起来，并作为单个序列的 token 流送入解码器-only 的 Transformer（即 Hunyuan-A13B 骨干网络）**。
    
 3. “单序列统一”的优势

这种将 VAE（生成特征）和 Vision Encoder（理解特征）融合到**同一个连续序列**中的方法是 HunyuanImage 3.0 与先前统一模型（如 Flamingo、JanusFlow 等）的一个关键区别。

- **统一多模态表示：** 它打破了传统模型中视觉特征按任务隔离的模式（例如，使用 Vision Encoder 特征进行理解，使用 VAE 特征进行生成）。
    
- **消除流程切换：** 模型可以在**一个连续的上下文**中处理复杂的**多模态交互**，例如：
    
    - **文本对话**
        
    - **图像生成**
        
    - **图像理解**
        
    - **图像编辑**
        
    - **交错的文本-图像输入**

### 2. 高质量数据和推理能力

- **三阶段数据过滤：** 对超过 100 亿原始图像进行了严格的过滤，重点关注语义多样性和图像质量。包括：
    
    - **AIGC 内容缓解：** 结合自动化 AIGC 检测模型和移除高比例 AIGC 内容的数据源，以保持自然数据分布。
        
    - **主观评分操作符：** 使用学习型检测器（如清晰度模型和自定义美学模型）对图像进行评分和筛选。
        
- **创新的图像字幕生成管线（Image Captioning Pipeline）：**
    
    - **双语和分层字幕模式：** 将图像内容分解为多个语义字段，包括描述级别（短到超长）、**风格属性**和**事实实体（IP、品牌、艺术品）**，以实现对生成过程的细粒度控制。
        
    - **事实基础（Factual Grounding）：** 集成了 **OCR Agent** 和 **Named Entity (IP) Agent** 等专业代理，并通过**双向验证循环**来确保生成的描述与现实和世界知识一致。

## Sora
### 1. 核心架构：Diffusion Transformer (DiT)

Sora 的核心是结合了**扩散模型**和**Transformer**的架构，这种组合被称为 **Diffusion Transformer (DiT)**，灵感来源于 Scalable Diffusion Models with Transformers 论文。

- **扩散模型（Diffusion Model）：** Sora 是一个**潜在扩散模型**（Latent Diffusion Model, LDM）。它在训练过程中学习如何逐步消除随机噪声，将一个噪声的潜在表示（Latent Representation）转化为连贯的视频。
    
- **Transformer：** 在扩散模型的去噪步骤中，Sora 使用一个**巨大的 Transformer** 来处理潜在表示，而不是传统的 U-Net 结构。Transformer 的**全局注意力机制**使其能够比 U-Net 更有效地建模**长距离的时空依赖性**，这对于生成长时间、高一致性的视频至关重要。
    

### 2. 统一的数据表示：时空 Patch (Spacetime Patch)

这是 Sora 最具创新性的技术点，它统一了不同模态和分辨率的数据：

- **将视频视为 Patch 集合：** Sora 的关键突破在于，它将**任何分辨率、持续时间、纵横比**的视频（或图像）都首先压缩到**潜在空间**（使用 VAE 变体），然后切分成统一的**时空 Patch**。
    
- **统一的输入格式：** 无论是高分辨率的视频、低分辨率的视频，还是单个图像，在进入 Transformer 之前，都被转化为**一系列 Patch token**。这使得模型可以：
    
    - 在**不同时长和宽高比**的数据上进行训练，极大地提高了数据效率。
        
    - 将视频生成问题转化为一个**对 Patch 序列的预测问题**，完美契合 Transformer 的输入要求。
        

### 3. 可变时长和分辨率

- 得益于时空 Patch 结构，Sora 可以原生支持**可变分辨率、可变时长和可变纵横比**的视频生成。
    
- 模型学会了在**原始尺寸**（Native Size）下进行训练和生成，避免了将所有数据缩放到统一尺寸带来的质量损失。
